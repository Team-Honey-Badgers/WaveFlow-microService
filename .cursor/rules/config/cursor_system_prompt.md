다음은 Cursor(에이전트)가 WaveFlow 프로젝트를 빠르게 이해하고, 일관된 답변과 제안을 할 수 있도록 만든 가이드라인입니다.

## 1. 프로젝트 개요
- **프로젝트명**: WaveFlow – “보컬만 바꿔도 전체 곡을 덮지 않아도 되는, 악기별 독립 버전 관리 협업 플랫폼”
- **문제 정의**:
  - 기존 음악 협업은 WAV 파일을 카톡/드라이브로 주고받아 버전·충돌 관리 불가능

## 2. 핵심 목적 및 페르소나
- **목적**: 음악(stem) 단위로 버전 관리→PR 기반 리뷰→best 브랜치(최종 대표 스템) 구성
- **페르소나(MVP 단계)**:
  - 래퍼 지망생(디지털 숙련도 보통)도 직관적 UI로 stem 버전 관리 가능

## 3. 주요 개념 정의
| WaveFlow 용어           | Git 용어       | 의미                                                      |
|-------------------------|----------------|-----------------------------------------------------------|
| 작업자 작업 공간 (브랜치) | branch         | 개인 stem 작업 공간 (e.g. user-민)                        |
| stem 업로드 (커밋)       | commit         | WAV 파일 업로드 단위                                       |
| 승격 요청 (PR)          | pull request   | 작업자 브랜치→best 브랜치로 승격 요청                     |
| best 브랜치             | main           | 프로젝트에서 현재 “가장 좋은” stem들만 모아둔 상태        |
| 승격 (Merge)            | merge          | PR 승인 후 best 브랜치에 반영                              |

## 4. 주요 기능
1. **Stem 관리**
   - AI 기반 분리(Spleeter/Demucs) → MFCC·RMS 등 fingerprint 생성 → SHA-256 해시로 버전 식별
2. **Diff 분석 & 시각화**
   - 파형·스펙트로그램·벡터 비교 → GUI 상에서 AB 비교 및 히트맵 제공
3. **PR 워크플로우**
   - 자동 유사도 계산 → 대표자 청취 후 수락 여부 결정 → best 브랜치 반영
4. **권한 관리(RBAC)**
   - 믹싱 엔지니어·보컬·프로듀서 등 역할별 접근 제어

## 6. 데이터 모델 핵심 테이블
- - **User**, **Project**, **Branch**, **Stem**, **Version**, **PullRequest**
- `Version` 레코드: fingerprint 해시, 유사도(score), 메타데이터
- 각 Version 레코드에 fingerprint 해시·유사도·메타데이터 저장

## 7. MVP 범위 & 개발 일정
| 기능          | 포함 여부 | 설명                                      |
|---------------|----------|-------------------------------------------|
| 회원가입/로그인 | ✅       | 이메일 기반, JWT 인증                    |
| 프로젝트 생성  | ✅       | 이름·설명·커버·stem 파일 업로드           |
| Stem 업로드   | ✅       | 단일 WAV 파일 drag&drop  |
| Stem 버전관리 | ✅       | stem별 히스토리 확인, 기본 롤백·롤포워드    |
| PR/리뷰        | ❌       | Diff 기반 UI, 승인 흐름은 차후 추가 예정   |

- **개발 기간**: 1주차 인프라 구축 → 2주차 버전관리 → 3주차 AI 통합 → 4주차 폴리싱 & 배포

## 8. UX·UI 철학
- **비개발자 친화적**: Git 용어 숨기고 “작업 공간”/“승격 요청” 등 직관적 용어 사용
- **시청각 중심**: AB 비교 청취 UI, 그래프에 해설 텍스트 병기
- **커스터마이징**: 사용자가 UI 배치·테마 조정 가능
